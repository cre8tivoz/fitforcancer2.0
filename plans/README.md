## Findings considered and rejected (do not re-audit)

- **Gemini API key sent as URL query param** (`api/gemini.ts:279`) — folded into plan 003 (moved to `x-goog-api-key` header), not a separate plan.
- **`api/rateLimit.ts` is deployed as a (non-functional) serverless endpoint** because every non-underscored file in `api/` becomes a function — harmless surface; optional rename to `api/_rateLimit.ts` is a conditional step in plan 004's scope.
- **Duplicate initial assistant message** (`App.tsx:153` `INITIAL_CHAT_MESSAGES` vs the inline copy at `App.tsx:168-173`, which diverge by an en dash) — cosmetic dead-code duplication; not worth a plan. Fix opportunistically if a future plan already edits that region.
- **Patient health context stored unencrypted in localStorage** — by design per `SECURITY.md` ("Local privacy model"): no accounts, no server-side health records, 14-day expiry. Not a finding.
- **In-memory rate limiter as a *vulnerability*** — it is a documented, accepted trade-off (`SECURITY.md:23`); plan 004 implements the upgrade path the doc itself names, rather than treating it as an unknown defect.
- **`x-forwarded-for` spoofing of the rate-limit key** — on Vercel the platform controls this header; not actionable from app code.
